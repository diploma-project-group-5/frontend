# web — веб-клієнт «Лад»

React SPA за специфікацією MVP «Лад» (v24, 03.11.2026): кабінети системного адміна й укладача
розкладу, публічні сторінки за QR (`/c#токен`, `/t#токен`) і аркуші для друку.

Віддається статикою через шлюз Traefik на `/`. Вхід — Keycloak за `/idp`, API — `/api/v1/*`
(усе одне походження, тож CORS не потрібен).

## Стек

| Що           | Вибір                                                  | Чому                                                                |
| ------------ | ------------------------------------------------------ | ------------------------------------------------------------------- |
| Збірка       | Vite + React 19 + TypeScript (strict)                  | статичний SPA, швидка збірка                                        |
| Маршрути     | React Router (data router, ліниві чанки)               | сторінки за QR не завантажують keycloak-js і код кабінету           |
| Дані сервера | TanStack Query                                         | кеш, опитування `GET /jobs/{id}`, `retry` лише для 5xx              |
| Вхід         | keycloak-js, Authorization Code + PKCE (S256)          | розділ 08; окремих `/login`, `/refresh`, `/me` немає                |
| Стилі        | CSS Modules + токени з прототипу, шрифт Onest у збірці | CSP `default-src 'self'`: жодних сторонніх шрифтів і CDN            |
| QR           | `qrcode.react` (SVG у браузері)                        | друк — HTML + print-CSS, без серверних PDF                          |
| Час          | date-fns + @date-fns/tz                                | «сьогодні», ISO-тиждень і +7 днів — у Europe/Kyiv, не зоні браузера |
| Тести        | Vitest + Testing Library                               |                                                                     |

## Запуск

Потрібен Node 24 (`.nvmrc`; мінімум 22.22).

```bash
nvm use
```

```bash
npm install
```

```bash
npm run dev
```

Dev-сервер на `http://localhost:5173` проксює `/api` і `/idp` на `DEV_PROXY_TARGET`
(за замовчуванням `http://localhost` — стенд `platform` у docker compose). Змінні — у `.env.example`.

### Без бекенда: мок-режим

```bash
npm run dev:mock
```

Keycloak і сервіси не потрібні: вхід фейковий, `/api/v1/*` обслуговує `src/mocks` (демо-заклад
«Ліцей № 17»). У прод-збірку мок-код не потрапляє.

- кнопка «Змінити роль» унизу меню — перемикає укладача ↔ системного адміна;
- «Побудувати розклад» — задача проходить queued → running → done приблизно за 4 с;
- публікація з `stale` у номері наказу → `409 stale`; реєстрація з логіном `taken` → `409 login_taken`;
- сторінки за QR: `/c#demo-class`, `/t#demo-teacher`; будь-який інший токен → «Посилання недійсне».

Стан мока живе в пам'яті вкладки й скидається після перезавантаження.

Перевірки (те саме, що в CI):

```bash
npm run check
```

## Структура

```
src/
  api/        http-клієнт (problem+json → ApiError), ендпоінти сервісів, типи, опитування задач
  auth/       keycloak-js, AuthGate, перевірка ролей sysadmin / scheduler
  app/        маршрути
  layouts/    кабінет з меню
  lib/        час у Europe/Kyiv, токен QR
  pages/
    admin/      реєстрація закладу (тимчасовий пароль показується один раз), список закладів
    scheduler/  розділи укладача (див. нижче); data/ — вкладки «Дані закладу»
    public/     сторінки за QR — без акаунта
    print/      аркуші QR класів і вчителів (print-CSS)
  ui/         токени, базові компоненти
nginx/        конфіг віддачі статики з заголовками безпеки
```

## Що готово, а що ні

Розділи кабінету укладача — як у прототипі; вміст — за API специфікації v24:

| Розділ       | Що є                                                                                                                                                                                                                                                                                                                                                                                                                    | API                                                                                                     |
| ------------ | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------- |
| Дані закладу | вкладки Заклад (профіль і основні дзвінки — редагування), Календар (канікули — одна пара дат), Класи (додати, редагувати, архівувати, QR у рядку, QR усіх класів), Вчителі (додати, редагувати, QR; етап 2 — експорт JSON і видалення → «Вчитель #N»), Предмети (додати, редагувати, архівувати), Навчальний план (години й вчитель для кожного класу × предмета, попередження про ліміт вчителя, збереження одним PUT) | `/school`, `/bells`, `/classes`, `/teachers`, `/subjects`, `/curriculum`, `/holidays`, `/access-tokens` |
| Розклад      | `:build` → 202 → опитування задачі; версії «запланована / чинна / архівна»; сітка по днях, навантаження укриття                                                                                                                                                                                                                                                                                                         | `/timetables:build`, `/jobs/{id}`, `/timetables`, `/timetables/{id}`, `/load`                           |
| Погодження   | вибір перевіреної версії, зміни форматів днів відносно чинної, `:publish` з наказом, `409 stale`, `lost_substitutions`                                                                                                                                                                                                                                                                                                  | `/timetables/{id}:publish`                                                                              |
| Заміни       | заглушка — етап 2                                                                                                                                                                                                                                                                                                                                                                                                       | `/absences`, `/substitutions`                                                                           |
| Сценарії     | звичайний ↔ тривоги: облік тривог з рекомендацією, побудова й погодження плану 1.2, активація з дати, повернення                                                                                                                                                                                                                                                                                                        | `/alert-plan*`, `/alert-hours`                                                                          |
| Журнал       | журнал дій за період                                                                                                                                                                                                                                                                                                                                                                                                    | `/audit`                                                                                                |

Також: вхід через Keycloak з розведенням за роллю; адмін — реєстр закладів як у прототипі (пошук,
реєстрація у вікні, одноразовий показ тимчасового пароля) на `GET/POST /schools`; сторінки `/c` і `/t` — два тижні, очно / дистанційно,
«Заміна», банер, однаковий текст для 404.

Ще не зроблено: дзвінки тривог (`PUT /alert-plan/bells`); етап 2 —
ручна правка уроку, заміни. Видалення й експорт вчителя (етап 2) уже в інтерфейсі; якщо маршрут
експорту timetable ще не готовий, вікно експорту показує частину school і пояснення.
Предмети вчителя в API не зберігаються, тому «Предмети» й «Годин / ліміт» на вкладці «Вчителі»
рахуються з навчального плану.

Свідомо не перенесено з прототипу, бо специфікація v24 вирішила інакше: вибір моделі основного
розкладу (завжди 1.1), запрошення укладача поштою (замість цього — логін і тимчасовий пароль),
перемикач «показувати підписи вчителів за QR» (учні їх не бачать ніколи), статуси закладів, останній
вхід, скидання пароля, блокування й журнал дій адміна (у v24 цього API немає — лише вручну в
Keycloak). Сторінка входу — це сторінка Keycloak (`/idp`); вигляд як у прототипі робиться темою
Keycloak у репозиторії `platform`.

## Домовленості

- **Типи API** у `src/api/types.ts` написані вручну за специфікацією; поля, яких вона не фіксує,
  позначено `// припущення`. Коли `contracts` опублікує пакет з OpenAPI-типами — замінити реекспортом.
- Поля — `snake_case`, як в API; не перетворюємо їх у camelCase.
- Заклад береться з JWT — у шляхах його немає.
- Токен QR — лише у фрагменті URL і заголовку `X-Access-Token`, ніколи в query чи логах.
- На сторінках за QR не показуємо назву закладу, підписи вчителів на сторінці класу, місткість.

## Docker

```bash
docker build -t lad-web .
```

Образ на `nginx-unprivileged`, порт `8080`, `/healthz`. На `main` CI публікує
`ghcr.io/<org>/web:<sha>`; викатка — зміною тегу в репозиторії `platform`.
